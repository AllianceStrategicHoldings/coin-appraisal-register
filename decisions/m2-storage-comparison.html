Cloud Storage: Options Comparison

Where photos and generated offer-letter PDFs are stored and served — AWS S3 versus Cloudflare R2.

Prepared by Flowtive · kristof@getflowtive.com · July 2026

Section 2.12 requires all photos (intake lot, driver's licence, acceptance lot, item photos) and all generated PDFs (signed offer letters) stored in the cloud with the URL written to the deal record, via a presigned-URL upload flow from the PWA. Both options below use the same S3-compatible API, so the build effort is identical — the decision comes down to cost and operational fit, not engineering.

Criterion AWS S3 Cloudflare R2
API & build effort S3 SDK Same S3 SDK — identical code
Egress (data out)Photos + PDFs served back to app, dashboard, GHL, customers $0.09 / GB — every view is billed Free — no egress charges
Storage cost ~$0.023 / GB / mo ~$0.015 / GB / mo
Billing model Metered — grows with usage Flat, predictable
Free tier 5 GB (first 12 months only) 10 GB ongoing
Maturity / ecosystem The industry standard; everything supports it Younger, but mature for object storage
Presigned-URL upload flow Fully supported Fully supported — same flow
Best fit when Already standardised on AWS App serves images / PDFs back out constantly
Recommendation

Cloudflare R2. Because it speaks the same S3 API, the build is identical either way — so the deciding factor is cost. This app doesn't just store files; it serves them back out repeatedly (offer-letter PDFs pulled by GHL, photos shown in the manager dashboard, customer-facing views). On S3 every one of those is billed egress; on R2 that's free, giving a predictable flat bill instead of one that grows with usage. The only reason to choose S3 instead is if the operator is already standardised on AWS and wants everything under one roof.
